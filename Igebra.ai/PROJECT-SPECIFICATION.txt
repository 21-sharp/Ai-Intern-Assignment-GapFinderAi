
PROJECT: GAPFINDER AI
TYPE: Multi-User AI-Powered SaaS Learning Platform
OBJECTIVE: Build a complete, secure, scalable, production-ready website from scratch.

==================================================
1. PRODUCT VISION
==================================================

Build GapFinder AI, an intelligent personalized learning
platform that identifies what students do not understand.

The application must behave like a diagnostic system
for education.

It must not function merely as an AI chatbot.

CORE WORKFLOW:

Student Registration
        ↓
Upload Study Materials
        ↓
Extract and Process Documents
        ↓
Build Syllabus Topic Map
        ↓
Map Previous Exam Questions
        ↓
Generate RAG-Based Diagnostic Quiz
        ↓
Evaluate Student Answers
        ↓
Identify Knowledge Gaps
        ↓
Generate Personalized Revision Plan
        ↓
Student Studies Weak Topics
        ↓
Conduct Another Test
        ↓
Update Knowledge Gap Report
        ↓
Update Revision Plan

The main product output is a measurable diagnosis
of the student's knowledge gaps.

==================================================
8. RAG IMPLEMENTATION (MANDATORY)
==================================================

Implement a genuine Retrieval-Augmented
Generation architecture.

DOCUMENT INGESTION:

1. Extract text from uploaded material.
2. Split text into meaningful chunks.
3. Preserve page and section metadata.
4. Generate embeddings.
5. Store vectors in pgvector.
6. Index document metadata.

RETRIEVAL:

1. Receive a user query or topic.
2. Generate its embedding.
3. Search the user's authorized documents.
4. Retrieve the most relevant chunks.
5. Apply relevance thresholds.
6. Optionally rerank results.
7. Return source metadata.

GENERATION:

1. Send retrieved chunks to the LLM.
2. Provide explicit instructions to use the
   supplied context.
3. Generate the required response.
4. Validate structured output.
5. Attach source citations.
6. Check whether citations support the answer.

RAG SECURITY:

- Never search unrestricted global student documents.
- Apply ownership and tenant filters during retrieval.
- Do not trust instructions embedded in uploaded PDFs.
- Treat document text as untrusted data.
- Do not allow retrieved content to override
  system instructions.
- Do not generate unsupported citations.
- Return an insufficient-evidence response when
  retrieval confidence is too low.

Clearly separate:

RETRIEVAL = Finding information in uploaded materials.

GENERATION = Creating questions and explanations
using retrieved information.

EVALUATION = Assessing student answers.

ANALYSIS = Finding learning weaknesses.

PLANNING = Converting weaknesses into revision tasks.

Every generated question must retain its source
document, page and section wherever available.

==================================================
11. KNOWLEDGE GAP ANALYSIS ENGINE
==================================================

THIS IS THE MOST IMPORTANT MODULE.

Analyze student performance at topic and subtopic
levels.

For each topic calculate:

- Questions attempted.
- Correct answers.
- Incorrect answers.
- Accuracy.
- Average marks.
- Difficulty-adjusted performance.
- Previous attempt performance.
- Learning trend.
- Evidence of misunderstanding.

INITIAL CLASSIFICATION:

Accuracy below 50% = WEAK
Accuracy 50–79% = MEDIUM
Accuracy 80–100% = STRONG

These thresholds must be configurable.

Require sufficient question evidence before
assigning a confident mastery classification.

GAP REPORT:

RED:
Weak topics requiring focused revision.

YELLOW:
Partially understood topics requiring practice.

GREEN:
Topics showing good understanding.

Each report must include:

- Topic name.
- Mastery level.
- Accuracy percentage.
- Questions attempted.
- Reason for weakness.
- Common mistakes.
- Suggested learning material.
- Recommended practice.
- Trend compared with previous attempts.

Never fabricate a reason for a weakness.
Use actual incorrect answers and their concepts
as evidence.

12. PERSONALIZED REVISION PLANNER
==================================================

Collect:

- Examination date.
- Available study days.
- Daily study hours.
- Preferred study time.
- Subject priorities.

Calculate a priority score using:

Priority =
0.6 * (1 - topic_accuracy)
+
0.4 * exam_importance

Both values must be normalized from 0 to 1.

Create a revision schedule.

Each task contains:

- Date.
- Topic.
- Subtopic.
- Duration.
- Priority.
- Recommended material.
- Practice activity.
- Completion status.

PLANNER REQUIREMENTS:

- Prioritize weak topics.
- Consider examination importance.
- Respect available study time.
- Prevent scheduling beyond available hours.
- Include practice and revision.
- Allow manual task editing.
- Allow task completion.
- Recalculate after new quiz attempts.

Do not discard the old plan.
Keep revision plan history.
